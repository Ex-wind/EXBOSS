# EXBoss 12.1 新版光环音效开发计划

> 状态：单表 V2 已实施；待游戏内回归
> 最后更新：2026-08-07
> 范围：大秘境副本级「玩家减益 / 敌方增益」音效设置与运行时注册

## 1. 目标与边界

将现有按首领卡片展示的私人光环音效，重构为按副本统一管理的光环音效列表。一个副本只保留一个入口，列表包含该副本所有需要关注的：

- 玩家身上的敌方减益；
- 敌方单位身上的敌方增益。

每行独立保存启用状态与音效选择，跟随当前副本、当前专精槽位和作者配置；其数据必须随 BossConfig 场景导出、导入。

本轮明确不包含以下内容：

- 不创建、不修改、不迁移 [PrivateAuraMonitorPage.lua](ExBossGUI/SettingsPage/PrivateAuraMonitorPage.lua) 的私人光环图标/锚点项目；
- 不保留「创建私人光环图标」作为新版光环音效的一部分；
- 不新增每个 Boss 各自的光环设置页面。

## 2. 已确认的 12.1 API 与限制

12.1 正式 API 为：

```lua
local id = C_UnitAuras.AddAuraSound(Enum.UnitAuraSoundTrigger.Added, {
    unitToken = "player",
    spellID = spellID,
    soundFileName = soundPath,
    outputChannel = "Master",
})
C_UnitAuras.RemoveAuraSound(id)
```

`UnitAuraSoundInfo` 的字段为 `unitToken`、`spellID`、`soundFileName`、`soundFileID`、`outputChannel`；触发器为 `Added`、`ApplicationsIncreased`、`Removed`。本模块只使用上述正式 API，不保留兼容调用。

该 API 带受限标记，且参数仅可在未污染环境下传入。实现必须遵守：

- 音效注册/注销只使用本地静态配置、稳定 spellID、已解析的音效路径和明确的 unitToken；
- 不扫描 `UNIT_AURA`，不读取或比较秘密 aura 字段，也不把 `auraInstanceID` 持久化；
- 不以 `pcall` 掩盖注册或注销错误；应保存可诊断的失败原因，并在受限状态结束后重试；
- 副本/战斗/大秘境/PvP 受限期间不重建注册，沿用旧运行时的延迟刷新思路。

### 已实测的注册结论（2026-07-17）

以下为实际客户端测试结果，应作为运行时限制：

| 项目 | 结论 |
| --- | --- |
| 已验证的 `unitToken` | `player`、`party1`–`party4`、`target`、`nameplate1`–`nameplate40` |
| `/reload` | 已注册音效会被客户端自动注销，插件必须重新注册 |
| 大秘境非战斗 | 可以注册 |
| 大秘境战斗中 | 不能注册 |
| 非大秘境战斗中 | 可以注册 |
| 首领战中 | 不单独处理；本模块仅在大秘境启用，首领战属于大秘境战斗中，按不可注册处理 |

这意味着大秘境中掉线重登或 `/reload` 后，音效注册会消失；新版运行时必须在 `PLAYER_ENTERING_WORLD` 后主动恢复。若恢复时仍处于大秘境战斗或首领战，则只标记 pending，在下一次允许注册的窗口立即恢复，不能尝试在受限期强行调用 API。

### 敌方增益仍需完成的验证

API 文档未说明敌方单位令牌的完整适用范围；已确认 `target` 与 `nameplate1`–`nameplate40` 可作为注册令牌，仍须验证：

1. 名字板出现、消失、序号复用时的重注册和清理；
2. 一个 spellID 对多个敌方单位的注册去重和清理规则；
3. `bossN` 的实际可用性及其与名字板的优先策略。

运行时默认覆盖 `target`、`boss1`–`boss5`、`nameplate1`–`nameplate40`；若实际出现 `bossN` 兼容问题，再单独调整。

## 3. 现状盘点

| 区域 | 当前实现 | 新版处理 |
| --- | --- | --- |
| WCL 数据 | `EXDATE/wcl_buff_debuff_excel.py` 已按 NPC 收集「敌方施加给玩家的 Debuffs」和「敌方施加给敌方的 Buffs」 | 作为新版候选数据入口；先人工筛选，再生成插件静态数据 |
| 旧数据生成 | `EXBOSSPY/3.PrivateAura/_内部模块/builder.py` 仅根据 SpellMisc 的 Private Aura 标志生成 `PrivateAuraData.lua` | 不可直接复用为新版全集；应新增专用的光环音效数据管线和 schema |
| 旧静态数据 | `EXBossData/PrivateAuraData.lua` 按团本首领 / 大秘境副本保存 spell、来源 NPC、Boss 归属、语音分类 | 大秘境部分可迁移为候选来源；不应继续以 Boss 归属决定 UI |
| 旧运行时 | `Modules/PrivateAura/Runtime.lua` 收集当前场景行、解析语音、保存 registration ID，并于进图/换区/配置变更刷新 | 保留「集中注册、集中注销、延迟重试」的结构，替换为新 API 和副本级配置 |
| Boss 页面 | `BossPage.lua` 会把私人光环混入当前 Boss 的法术卡片，并在右侧渲染单条音效设置 | 删除该卡片/详情设置入口，改为副本通用设置中的表格 |
| 配置与导入导出 | `BossConfig` 已有 `dungeonOptions`，且 `ExportScene` / `ImportScene` 已会保存和恢复它 | 扩展 `dungeonOptions[dungeonKey]`，无需另建独立模块 DB |
| 批量编辑 | `BatchEditPage.lua` 仍有旧私人光环分类与语音替换 | 本次切换时移除或改为新版副本光环音效作用域；不得继续写旧 `privateAura` |

现有 `PrivateAura` 运行时仍调用旧别名，并对 API 使用 `pcall`。新版不得复制这一做法。

## 4. 新数据模型

### 4.1 静态副本数据

新增独立静态数据表 `EXBossData/AuraSoundData.lua`，只保存经 Excel 标记导出的候选，不保存用户选项。结构：

```lua
EXBOSS_AURA_SOUND_DATA = {
    [dungeonKey] = {
        mapID = 2993,
        entries = {
            ["player_debuff:123456"] = {
                key = "player_debuff:123456",
                unitScope = "player_debuff",
                spellID = 123456,
                sourceNPCIDs = { 12345 },
                sourceNames = { "NPC 名称" },
            },
            ["enemy_buff:234567"] = {
                key = "enemy_buff:234567",
                unitScope = "enemy_buff",
                spellID = 234567,
                sourceNPCIDs = { 23456 },
                sourceNames = { "NPC 名称" },
            },
        },
    },
}
```

`dungeonKey + unitScope + spellID` 是稳定主键。不得以 Boss 名称、语言文本或 `auraInstanceID` 作为保存键。法术名与图标在 GUI 使用 `spellID` 查询，静态表可保留抓取时的后备文本。

### 4.2 用户/作者配置

配置归入已有的副本通用根：

```lua
userOverrides[slotKey][authorKey].dungeonOptions[dungeonKey] = {
    -- 既有副本通用开关保持原状
    auraSounds = {
        version = 2,
        nextCustomID = 1,
        items = {
          ["user:1"] = {
            spellID = 123456,
            unitScope = "player_debuff",
            category = "targeted",
            trigger = "added", -- added / applicationsIncreased / removed
            sourceType = "pack", -- pack / lsm
            label = "...",       -- 语音包标签
            customLSM = "...",   -- LSM sound key
            outputChannel = "Master",
          },
        },
    },
}
```

一条 `items[actionID]` 就是一条独立的声音注册；同一光环、同一状态的多个声音使用多个 actionID。新版只提供「语音包」与「LSM」两种来源，不提供任意文件路径输入。不存在行即不注册；不持久化 API 返回的 `auraSoundID`、展开后的 unitToken 或解析后的声音路径。预设、用户覆盖和导入后的合并顺序继续采用当前 BossConfig 的 defaults → preset → user 规则。

### 4.3 导入导出

`BossConfig:ExportScene` 已包含每个槽位的 `dungeonOptions`，`ImportScene` 也会写回该字段。实施时须补充：

- `auraSounds` 的 schema 标准化、合法 key 校验及 LSM key 规范化；
- 导出内容保存副本键和稳定行键，绝不保存运行时 registration ID 或 unitToken；
- 导入后触发新版运行时刷新；
- 旧 `privateAura` 数据不再是新版导出的有效来源。迁移策略必须明确为一次性转换或明确丢弃，禁止双写。

## 5. GUI 设计

入口继续使用刚建立的 Boss 页面「副本通用设置」卡片；选择后右侧内容分为：已有通用开关区与新增的「光环音效」区。所有行属于当前副本，不随左侧选中的具体 Boss 变化。

表格固定列为：

| 图标 | 法术名称 | 分类 | 状态 | 播放的声音 | 编辑 |
| --- | --- | --- | --- | --- | --- |
| 法术图标 | 法术本地化名称 + spellID | 稳定分类 key 的本地化显示 | 添加 / 叠层 / 移除 | 语音包标签或 LSM 名称 | 修改或删除该 action |

具体规则：

- 每一行均是一个 action；没有勾选框或来源列，删除 action 即停用该声音；
- 「+ 添加声音」创建用户 action，编辑器中填写法术 ID、类型、分类、状态、来源与声音；
- 「语音包」下拉复用 `ExBoss.Voice.LabelCatalog.GetDropdownItems`；「LSM」复用已注册的 LibSharedMedia 音效；
- 分类字段用于未来按分类批量物理覆盖声音，不参与 API 注册匹配；
- 表格单行直接写回当前 `dungeonOptions[dungeonKey].auraSounds.items[actionID]`，不再打开旧私人光环详情卡，也不再使用 `ExBoss.PrivateAuraOptions` Grid 模块；
- 音效试听走 `Voice.Engine:TryPlayStandaloneSound`，而真正的 aura 提示由 Blizzard API 播放。

## 6. 运行时设计

新增独立模块 `Modules/AuraSound/Runtime.lua`，不再加载 `Modules/PrivateAura/Runtime.lua`。职责如下：

1. 根据当前实例、当前副本键、当前角色槽位和作者，读取已解析的 `auraSounds`；
2. 遍历已解析的 `auraSounds.items`，仅处理能解析出语音包/LSM 文件的 action；
3. 使用 `Voice.Engine:ResolveStandaloneSound` 解析为文件路径、输出通道；
4. 对每一条实际注册保存 API 返回的 `auraSoundID`，运行时键为 `actionID + unitToken`；
5. 以配置指纹做差量更新：仅移除过期/改变项并调用 `C_UnitAuras.RemoveAuraSound`，仅为新增/改变项调用 `C_UnitAuras.AddAuraSound`；
6. 以 `ExwindState.lua` 的 `InCombat`、`InInstance`、`InstanceID`、`MapID`、`InMythicPlus` 作为刷新判定真源；
7. 在 `PLAYER_ENTERING_WORLD`、区域变化、实例/地图/大秘境状态变化、角色槽位/作者切换、`dungeonOptions` 配置变更、导入完成时请求刷新。`PLAYER_ENTERING_WORLD` 必须在短延迟后补一次，专门恢复掉线重登或 `/reload` 自动注销的音效；
8. 大秘境战斗中只标记 pending，等 `PLAYER_REGEN_ENABLED` 和 `ADDON_RESTRICTION_STATE_CHANGED` 的下一次允许窗口刷新。首领战不单独判断，它本身就是大秘境战斗。

玩家减益的固定单位是 `player`。敌方增益须在第 2 节的前置验证完成后，采用验证过的敌方单位令牌维护方案；单位改变时只更新受影响的注册，不能通过读取秘密 aura 数据来判断状态。

## 7. 数据生产流程

1. 复用 `EXDATE/wcl_buff_debuff_excel.py` 的 WCL 抓取方向：
   - `Debuffs + Friendlies`：目标为玩家，再本地确认来源为敌方 NPC；
   - `Buffs + Enemies`：目标为敌方 NPC，再本地确认来源为敌方 NPC。
2. 以副本、NPCID、spellID、方向生成候选表；WCL 数据只代表出现过，不能自动等同于应提示项目。
3. Excel 按副本拆分 Sheet；在人工列中维护导出、黑名单、光环分类、默认语音标签和备注，人工排除常驻光环、无关光环、重复来源和无意义刷新。
4. 新生成器只输出审核通过的 `AuraSoundData.lua`，并保留来源 NPCID 以便后续校验与维护。
5. 旧 `EXBOSSPY/3.PrivateAura` 的作者分类、Boss 归属仅作迁移参考；新版不受 `SpellMisc` 的 Private Aura 标志限制。

## 8. 实施顺序

1. **已完成：数据管线**：`EXBOSSPY/4.光环语音` 已提供 WCL 同步、保留人工列的 Excel、Lua 导出；首版 Excel 按 8 个副本拆分 Sheet，含 360 条候选、图标、名称与描述（WCL 的无图标 `Encounter Event` 标记已排除）。根目录 `光环语音黑名单.json` 会被 WCL 同步与 Excel 生成读取；`同步光环语音黑名单.py` 将 Excel 黑名单列同步回 JSON。
2. **已完成：静态数据与运行时**：已生成 `AuraSoundData.lua`；运行时使用正式 `AddAuraSound` / `RemoveAuraSound` 的 action 差量注册，大秘境战斗中只排队，重登或 `/reload` 后自动恢复。
3. **已完成：GUI 与导入导出**：副本通用设置使用 V2 扁平 action 表；数据存入既有 `dungeonOptions`，随 BossConfig 场景导入导出。
4. **已完成：旧入口切换**：Boss 页面旧私人光环音效卡片已停用，旧私人光环运行时已从加载清单移除；私人光环图标监控页面不改动。
5. **待游戏内回归**：验证名字板序号复用、`bossN`、注册数量上限，以及导出→导入→重载后的实际提示。

## 9. 验收清单

- 同一副本 3–4 个 Boss 的所有审核行只在一个副本通用列表中出现；
- 玩家减益和敌方增益均能按已验证的单位令牌正确播放一次；
- 修改启用、语音包或 LSM 后，非受限状态立即重建注册；大秘境战斗/首领战等受限状态只在可用时重建；
- 离开副本、换副本、换角色槽位、换作者、导入配置后不会残留旧注册；
- 大秘境中掉线重登或 `/reload` 后，`PLAYER_ENTERING_WORLD` 会恢复已被客户端自动注销的音效；若此时在战斗中，则战斗结束后的首个允许窗口恢复；
- 场景导出后包含 `dungeonOptions[dungeonKey].auraSounds`，导入后结果一致；
- Boss 法术卡区域不再显示旧私人光环音效卡片；
- `PrivateAuraMonitorPage.lua` 及其私人光环图标功能没有改动；
- 不触碰秘密 aura 值，不扫描 aura 数据，不用 `pcall` 掩盖受限 API 失败。

## 10. 预计涉及文件

- 新增：`EXBossData/AuraSoundData.lua`、`Modules/AuraSound/Runtime.lua`、数据生成/审核脚本；

- 明确不修改：`ExBossGUI/SettingsPage/PrivateAuraMonitorPage.lua`。
